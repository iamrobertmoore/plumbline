A test plan is the same promise, in a spreadsheet. Somebody signs it before every release. Nothing checks it.

What it is

A Bob mode and a skill. Five stages.

Copy .bob/ into a repository, open it in IBM Bob, pick the Plumbline mode and ask it to audit.

01

Read

The .xlsx plan, .docx spec and .pdf checklist become claims, each with its source cell.

02

Map

One subagent per test file finds the test behind each case, even with no id in its name.

03

Break

A subagent that never sees the test makes the claim false and writes a witness. The runner applies it in a throwaway worktree.

04

Judge

Every spec clause and checklist tick against the code, the changelog and git history.

05

Report

One HTML report that leads with what is false.

Break it. Does the test notice?

TC-41: expired tokens are rejected. Delete the check. Still green.

test/tokens.test.mjsPASSES
test('TC-41 rejects an expired access token', () => {
  const t = issueAccess('ada@…', ['user'], { now });
  const result = verifyAccess(t, { now: now + 3h });
  assert.ok(result);  // always true
});
Bob's change, written without seeing the test
- if (claims.exp <= t - SKEW) return { …'expired' };
+ if (false)                  return { …'expired' };
Bob's witnessproves the break
const result = verifyAccess(t, { now: now + 2h });
return result.valid === false
    && result.reason === 'expired';
real code: true   broken code: false

The behaviour is gone, the witness proves it, and the test still passes. So does the whole suite.

Plumbline05

No accusation without proof

Every mutation tester can be fooled. This one has to prove it was not.

  • In the first run, 4 of 12 surviving changes did not really break the claim. So every accusation now needs a witness.
  • No witness: UNPROVEN. Witness wrong on real code: WITNESS_INVALID. Change harmless: WEAK_MUTATION.
  • Remove every witness and the same run accuses nobody.

How IBM Bob is used

Remove any one and the document tier stops working.

01

Custom mode

The Plumbline mode: role and allowed tools. .bob/custom_modes.yaml

02

Skills

Five stages, the claim schema, the cost rules. SKILL.md

03

Document understanding

Reads .xlsx and .docx as they are. For the .pdf, Bob wrote its own zero-dependency reader.

04

Subagents

One per test file to map, one per test file to break, with the test withheld.

05

Agent mode + commands

Runs the mutation runner, and read-only git to judge the spec against history.

06

Bob as the builder

Planned and wrote the mode, skill, runner, report and tests, and ran every audit.
